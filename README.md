# Medical AI Analyzer

Self-hosted web application for uploading a medical document or image, running an OpenAI-backed analysis pipeline, and reviewing the result in a browser. An account owner can inspect structured findings, edit extracted lab data, ask follow-up questions, and download a PDF.

Application version **1.0.0** (`frontend/package.json` and the FastAPI app version).

> **Medical disclaimer.** Output is generated by a general-purpose model. This project is not a medical device, it has no regulatory clearance, and it must not be used to diagnose, treat, or decide care. A licensed clinician has to interpret any real medical information. Read [Medical use](#medical-use) before uploading health data.

The landing page, pricing page, and security page contain marketing copy about diagnostic precision, paid plans, HIPAA, SOC 2, ISO 27001, encryption at rest, and cloud hosting. Those claims are not implemented in this repository. This document describes the code that actually runs.

## Capabilities

A signed-in user uploads a file. The API stores it, creates a report row, and processes it in a FastAPI background task. While any report is `pending` or `processing`, the dashboard reloads `GET /reports/list` every 3 seconds. `GET /reports/{id}/processing-status` exists for clients and is not called by the current pages.

Supported upload extensions, checked by filename only, are `pdf`, `png`, `jpg`, `jpeg`, and `tiff`. The browser also rejects files over 10 MB and checks the MIME type. The API does not enforce that size limit. The upload modal can send `user_notes`; the handler does not accept that field, so notes are not stored.

| Input the pipeline tries to handle | What the code does |
| --- | --- |
| Text-based PDF lab report | PyPDF2 reads the text layer. `gpt-4o` turns it into JSON. `MedicalAnalyzerAgent` writes the assessment. |
| Photo or scan of a lab report | `gpt-4o` vision reads the image, then the same analyzer runs. |
| X-ray, MRI, CT, or dental image | `MedicalImagingAgent` uses `gpt-4o` vision with a type-specific prompt. The analyzer returns without a second model call, and the imaging result is stored. |
| Ultrasound image | Detected as ultrasound and sent to the imaging agent with the **general** imaging prompt. There is no ultrasound-specific protocol. |
| Photo of an ECG/EKG or EEG tracing | `CardiacSignalAgent` or `NeurologicalSignalAgent` interprets the image with `gpt-4o` vision. The report is marked completed from that response. The medical analyzer is not called. |

There is no DICOM reader, waveform parser, or signal-processing library. ECG and EEG support means a vision model looking at a picture of a tracing.

PDFs are not rasterized. A scanned PDF with an empty text layer fails extraction with "Could not extract text from document". `pdf2image` and `pytesseract` are installed with the backend image, and Poppler and Tesseract are present in that image, but no application module calls them.

Image bytes are sent to the vision API as a `image/jpeg` data URL, including PNG and TIFF uploads.

After a report is `completed`, the same user can:

- Read severity, summary, findings, recommendations, and per-test rows on lab reports.
- Replace `extracted_data` and reprocess. Reprocess runs only `MedicalAnalyzerAgent` on the saved JSON.
- Chat about that report, including a server-sent-events stream.
- Transcribe an audio question with Whisper (`whisper-1`, language fixed to English) and synthesize speech with `tts-1` (voice `nova`, at most 4,000 characters).
- Download a ReportLab PDF. Its QR code targets `http://localhost:3333/reports/{report_id}`. The download helper does not take a public base URL.
- Read agent logs and per-user token and cost estimates.

Chat and voice require `analysis_status == completed`.

Severity values used by the schema are `normal`, `attention_needed`, `urgent`, and `critical`. They are model output stored in MySQL. They are not a validated triage scale.

### Present in the tree, not on the request path

- `ModeratorAgent` and `ToolsManager` are importable and are not called by the upload, reprocess, or chat routes.
- The `notifications` table is created. The UI methods that load notifications return an empty list in the browser and do not call the API.
- Redis is started by Compose because the API service waits for it. No backend module opens a Redis client.
- `backend/alembic.ini` exists. There is no `alembic/` revision directory. Tables are created with `Base.metadata.create_all` on startup. That creates missing tables and does not alter columns already in the database.
- `backend/env.example` lists upload limits, CORS origins, feature flags, and log rotation. The running code does not read those names. Extensions and CORS origins are hardcoded.
- Pricing tiers on `/pricing` are static page content. The API does not meter plans or take payment.

## Architecture

The browser loads the Next.js UI and calls the FastAPI origin directly. `next.config.js` does not proxy API requests. CORS is what allows the UI origin to talk to the API.

```mermaid
flowchart LR
  browser[Browser]
  frontend[Next.js on port 3333]
  api[FastAPI on port 5000]
  db[(MySQL)]
  files[Upload directory]
  openai[OpenAI API]

  browser -->|Pages| frontend
  browser -->|API calls| api
  api --> db
  api --> files
  api --> openai
```

Uploaded files are written under the backend `uploads/` directory, per user. In Compose that directory is the `backend_uploads` volume. MySQL and Redis are attached to the `app-net` bridge and are not published on the host. The UI and API are published on ports 3333 and 5000.

```mermaid
flowchart TD
  upload[File stored]
  classify[FileClassifierAgent]
  extract[DocumentExtractorAgent]
  cardiac[CardiacSignalAgent]
  neuro[NeurologicalSignalAgent]
  imaging[MedicalImagingAgent]
  analyzer[MedicalAnalyzerAgent]
  saved[Report saved]

  upload --> classify --> extract
  extract -->|ECG or EKG image| cardiac --> saved
  extract -->|EEG image| neuro --> saved
  extract -->|X-ray MRI CT dental ultrasound| imaging --> analyzer --> saved
  extract -->|Lab report text| analyzer --> saved
```

Classification calls `gpt-4o` on a text sample for PDFs and on the image for pictures. When that call succeeds and the model sets `is_medical` or `is_processable` to false, the report is stored as `failed` and extraction does not run. The background task reuses the request's SQLAlchemy session, and Compose starts one Uvicorn worker.

```mermaid
sequenceDiagram
  participant Browser
  participant API
  participant DB
  participant OpenAI
  Browser->>API: POST /api/v1/reports/upload
  API->>DB: Insert report as pending
  API-->>Browser: report_id and pending
  API->>OpenAI: Classify then extract and analyze
  API->>DB: Save findings and status
  Browser->>API: GET /reports/list while a report is pending
```

## Prerequisites

- Docker Engine with the Compose plugin, for the path below.
- An OpenAI API key if you want analysis, chat, or voice. The API process still starts when the key is empty. Voice then returns HTTP 503, and report processing fails when an agent is invoked.
- `curl` for the health and API examples. `openssl` is used to generate local secrets.

Local, non-Docker development also needs Python 3.12, Node.js 20, npm, and a reachable MySQL 8 server. That path was checked against the project files and was not executed in a clean environment for this document.

## Run with Docker

From a shell at the repository root:

```bash
git clone https://github.com/MohammadMoradpoor/medical-ai-analyzer.git
cd medical-ai-analyzer
```

### Environment file

Compose reads a root `.env`. That file is gitignored. Generate passwords and the JWT secret locally. Do not commit the file, and do not reuse the sample `SECRET_KEY` in `backend/env.example`.

```bash
read -rsp "OpenAI API key: " OPENAI_API_KEY && echo
MYSQL_PASSWORD="$(openssl rand -hex 18)"
MYSQL_ROOT_PASSWORD="$(openssl rand -hex 18)"
SECRET_KEY="$(openssl rand -hex 32)"

cat > .env <<EOF
MYSQL_DATABASE=medical_analyzer
MYSQL_USER=medicalai
MYSQL_PASSWORD=${MYSQL_PASSWORD}
MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
SECRET_KEY=${SECRET_KEY}
OPENAI_API_KEY=${OPENAI_API_KEY}
NEXT_PUBLIC_API_URL=http://localhost:5000/api/v1
ACCESS_TOKEN_EXPIRE_MINUTES=480
REFRESH_TOKEN_EXPIRE_DAYS=30
WORKERS=1
EOF
```

`NEXT_PUBLIC_API_URL` is a build argument for the production frontend image. Changing it requires `docker compose up -d --build`, not only a container restart.

If `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, or `SECRET_KEY` are omitted, Compose substitutes the development defaults written in `docker-compose.yml`. Set them before anyone else can reach the host ports.

`WORKERS` should stay at `1`. Startup creates tables in the application process, and the image is set up around that single worker.

### Start

```bash
docker compose up -d --build
```

| Service | Host URL | Role |
| --- | --- | --- |
| `frontend` | http://localhost:3333 | Next.js UI |
| `backend` | http://localhost:5000 | API. Interactive docs at `/docs` and `/redoc` |
| `db` | none on the host | MySQL 8.4 |
| `redis` | none on the host | Required by Compose health order, unused by the app |
| `adminer` | http://localhost:8080 | Only with the `tools` profile |
| `backend-dev` | http://localhost:5001 | Only with the `dev` profile |
| `frontend-dev` | http://localhost:3334 | Only with the `dev` profile |

The production backend and frontend images drop Linux capabilities, set `no-new-privileges`, and run as a non-root user. Memory limits in the Compose file are 1 GB for MySQL, 256 MB for Redis, 2 GB for the backend, and 1 GB for the frontend. The OCI source label in the Dockerfile still points at `https://github.com/your-org/medical-ai-analyzer`.


## Configuration

Variables the Compose file or the Python process actually use:

| Variable | Consumer | Role |
| --- | --- | --- |
| `MYSQL_DATABASE` | MySQL image and the composed `DATABASE_URL` | Database name. Default `medical_analyzer`. |
| `MYSQL_USER` | MySQL image and `DATABASE_URL` | Application user. Default `medicalai`. |
| `MYSQL_PASSWORD` | MySQL image and `DATABASE_URL` | Application password. |
| `MYSQL_ROOT_PASSWORD` | MySQL image and the database healthcheck | Root password. |
| `DATABASE_URL` | `backend/app/db/session.py` | SQLAlchemy URL. Compose sets `mysql+pymysql://...@db:3306/...`. A process started on the host must set this itself. |
| `SECRET_KEY` | `backend/app/auth/security.py` | HMAC secret for access and refresh tokens. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | access-token lifetime | Default `480`. |
| `REFRESH_TOKEN_EXPIRE_DAYS` | refresh-token lifetime | Default `30`. |
| `OPENAI_API_KEY` | agents, chat, and voice | Leave empty only if you are testing boot without model calls. |
| `NEXT_PUBLIC_API_URL` | frontend, including the production image build | Default `http://localhost:5000/api/v1`. |
| `WORKERS` | production container command | Uvicorn worker count. Use `1`. |
| `API_HOST`, `API_PORT` | container command | Set by Compose to `0.0.0.0` and `5000` inside the backend container. |

The login JSON field `expires_in` is fixed at `28800` seconds in the handler. That matches the 480-minute default. Changing `ACCESS_TOKEN_EXPIRE_MINUTES` changes the token expiry and does not change `expires_in`.

CORS origins are hardcoded in `backend/app/main.py` to `http://localhost:3000`, `http://localhost:3333`, and `*`, with credentials enabled. `CORS_ORIGINS` in `backend/env.example` has no effect.

Allowed extensions are hardcoded in the upload handler. `MAX_UPLOAD_SIZE` in `backend/env.example` has no effect. The 10 MB check lives in `frontend/lib/constants.ts`.

## Local development

Use Docker if you want the setup the Compose file already wires. The steps below follow the modules a host process actually imports.

The API imports ReportLab, `qrcode`, and Pydantic's `EmailStr`. Those packages are installed in the image and are absent from `backend/requirements.txt`. Install them or the process fails on import.

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install reportlab "qrcode[pil]" email-validator
cp env.example .env
```

Edit `backend/.env` and set at least:

```bash
DATABASE_URL=mysql+pymysql://USER:PASSWORD@127.0.0.1:3306/medical_analyzer
SECRET_KEY=replace-with-the-output-of-openssl-rand-hex-32
OPENAI_API_KEY=your-key
```

Create the database, then start the API from `backend/` so `load_dotenv()` finds `.env`:

```bash
mysql -u USER -p -e "CREATE DATABASE medical_analyzer CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
uvicorn app.main:app --host 0.0.0.0 --port 5000 --reload
```

`python -m app.main` listens on port 8000 instead. The frontend default is port 5000, so prefer the `uvicorn` command above. Do not run `alembic upgrade head`. There are no revision scripts. Tables are created when the application starts.

Frontend, with the API already on port 5000:

```bash
cd frontend
npm ci
printf 'NEXT_PUBLIC_API_URL=http://localhost:5000/api/v1\n' > .env.local
npm run dev
```

The UI is at http://localhost:3333. `npm run build` then `npm run start` matches the production frontend command.

## Using the application

1. Open http://localhost:3333 and create an account. The registration form requires a password of at least 6 characters. The register endpoint itself does not check length. The change-password endpoint does.
2. Sign in. The UI stores `access_token` and `refresh_token` in `localStorage`.
3. Upload a PDF or image from the dashboard or `/upload`.
4. Wait until the report status is `completed`. The dashboard refreshes the list while work is pending or processing.
5. Open the report to read the summary, findings, agent log, and chat panel.
6. For a lab report, edit extracted JSON and reprocess if you want the analyzer to run again on that JSON.
7. Download the PDF from the report view.

Direct API calls use the same routes. Registration does not return a token. Log in after creating the user.

```bash
API_URL="http://localhost:5000/api/v1"

curl -sS -X POST "$API_URL/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"email":"doctor@example.com","username":"doctor1","password":"StrongPass123","full_name":"Demo User"}'

curl -sS -X POST "$API_URL/auth/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=doctor1&password=StrongPass123"
```

The login body is form fields, not JSON. `username` matches either the username or the email. A successful login returns `access_token`, `refresh_token`, `token_type`, and `expires_in`.

```bash
TOKEN="<access_token from the login response>"

curl -sS -X POST "$API_URL/reports/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@/absolute/path/to/your-report.pdf"
```

The upload response field is `report_id`, together with `status` (`pending`) and `message`. Supply your own file. This repository does not include sample reports.

```bash
REPORT_ID="<report_id from the upload response>"

curl -sS -H "Authorization: Bearer $TOKEN" \
  "$API_URL/reports/$REPORT_ID/processing-status"

curl -sS -X POST "$API_URL/reports/$REPORT_ID/chat" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"Which values are outside the reference range?"}'
```

Chat returns HTTP 400 until analysis has completed. The streaming route uses `text/event-stream`. Each event is a JSON object with `type` of `content`, `done`, `message_id`, or `error`.

```bash
curl -N -X POST "$API_URL/reports/$REPORT_ID/chat/stream" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"Explain the abnormal values in plain language."}'
```

Voice transcription requires an `audio/*` content type. Text-to-speech returns audio bytes.

```bash
curl -sS -X POST "$API_URL/reports/$REPORT_ID/chat/voice" \
  -H "Authorization: Bearer $TOKEN" \
  -F "audio=@question.webm;type=audio/webm"

curl -sS -X POST "$API_URL/reports/$REPORT_ID/chat/text-to-speech" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"This is a short spoken summary."}' \
  --output speech.mp3

curl -sS -H "Authorization: Bearer $TOKEN" \
  "$API_URL/reports/$REPORT_ID/download-pdf" \
  --output medical_report.pdf
```

Refresh tokens are bound as a query parameter on the current handler:

```bash
curl -sS -X POST "$API_URL/auth/refresh?refresh_token=<refresh_token>"
```

`frontend/lib/api.ts` posts `refresh_token` as JSON instead. That client call does not match the handler signature.

## HTTP API

Base path: `/api/v1`. With the stack running, Swagger is at http://localhost:5000/docs and ReDoc is at http://localhost:5000/redoc. Unauthenticated probes: `GET /`, `GET /health`, and `GET /api/v1/auth/health`.

Every report, chat, and voice route below requires `Authorization: Bearer <access_token>`, and the report must belong to that user.

### Authentication

| Method and path | Body | Result |
| --- | --- | --- |
| `POST /auth/register` | JSON `email`, `username`, `password`, optional `full_name` and `phone` | User record. HTTP 201. |
| `POST /auth/login` | Form `username` and `password` | Access token and refresh token. |
| `POST /auth/refresh` | Query `refresh_token` | New token pair. |
| `GET /auth/me` | none | Current user. |
| `POST /auth/change-password` | JSON `current_password`, `new_password` | Confirmation. New password length must be at least 6. |

### Reports

| Method and path | Result |
| --- | --- |
| `POST /reports/upload` | Multipart field `file`. Returns `report_id`. |
| `GET /reports/list?limit=50&skip=0` | Reports for the current user. |
| `GET /reports/usage-stats` | Token totals, estimated USD cost, and breakdowns by model and agent. |
| `GET /reports/{report_id}` | Stored analysis, extracted JSON, and test rows. |
| `GET /reports/{report_id}/processing-status` | `pending`, `processing`, `completed`, or `failed`. While processing, includes a step label and a coarse progress percentage. |
| `PUT /reports/{report_id}/extracted-data` | Replaces the extracted JSON object. |
| `POST /reports/{report_id}/reprocess` | Runs the medical analyzer again on the saved JSON. |
| `GET /reports/{report_id}/agent-logs` | Agent log rows stored for that report. |
| `GET /reports/{report_id}/download-pdf` | Generated PDF. |
| `DELETE /reports/{report_id}` | Deletes the row and the stored file. |

Cost figures are bookkeeping inside the API. Where a log has a token total and no stored split, the usage endpoint assumes 60 percent input and 40 percent output. The rates recorded in code are 2.50 USD per million prompt tokens and 10.00 USD per million completion tokens. They are not an OpenAI invoice.

### Chat and voice

| Method and path | Result |
| --- | --- |
| `POST /reports/{report_id}/chat` | JSON `question` and optional `conversation_id`. |
| `POST /reports/{report_id}/chat/stream` | Same JSON body. SSE stream. |
| `GET /reports/{report_id}/chat/history` | Optional query `conversation_id`. |
| `GET /reports/{report_id}/chat/suggested-questions` | Question list for the report. |
| `POST /reports/{report_id}/chat/{conversation_id}/generate-title` | Short title. |
| `POST /reports/{report_id}/chat/{message_id}/feedback` | JSON `is_helpful` boolean, or `null` to clear it. |
| `DELETE /reports/{report_id}/chat/{message_id}` | Deletes one message. |
| `DELETE /reports/{report_id}/chat` | Clears history. Optional query `conversation_id`. |
| `GET /reports/chat/counts` | Chat counts across the user's reports. |
| `GET /reports/{report_id}/chat/stats` | Counts for one report. |
| `POST /reports/{report_id}/chat/voice` | Multipart `audio`. Returns `transcription`, `language`, and `duration`. |
| `POST /reports/{report_id}/chat/text-to-speech` | JSON `text`. Audio response. |

## Security and privacy

- Passwords are hashed with bcrypt. Sessions are JWTs signed with `SECRET_KEY`. Anyone with that secret can forge tokens.
- The browser keeps tokens in `localStorage`.
- Report queries filter on the authenticated user id. There is no separate role or organization model.
- Uploaded files are stored as ordinary files on disk. The application does not encrypt them at rest.
- Analysis, chat, and voice send file bytes, extracted text, or audio to OpenAI. A deployment that accepts real patient data needs a lawful basis for that transfer. This repository does not provide one.
- CORS allows `*` together with credentialed requests, and the API and UI ports are published on the host.
- There is no rate limit, MFA, audit-export tool, or backup job in the repo.
- The code and Compose file both have insecure defaults when `SECRET_KEY` or the MySQL passwords are left unset (`your-secret-key-change-in-production` in Python, and the defaults in `docker-compose.yml`).
- The `/security` page describes AES-256 at rest, HIPAA, SOC 2, ISO 27001, MFA, and AWS hosting. None of those controls are implemented here.

Set unique secrets, keep the host ports off the public internet, and assume model providers can see what you upload.

## Medical use

This is a software project that calls a general model and stores the text. It is not a clinical product.

- No validation study, sensitivity, specificity, or comparison with clinicians is included in the repository.
- No regulator has cleared or approved this software. Nothing in the repo is labeled as a medical device.
- Findings can be incomplete, invented, or confidently wrong. Reference ranges and measurements copied by the model can be misread.
- The PDF footer says the analyzer was trained on extensive medical datasets. The code calls the hosted `gpt-4o` API. This repository does not train or ship its own model.
- Imaging and signal agents apply a written prompt to a picture. They do not calibrate devices, measure pixels against a DICOM header, or review a full study.
- A PDF, a severity label, or a high confidence field in model JSON does not make the output safe to act on.
- Do not use the output as the only basis for a diagnosis, a medication change, or an emergency decision. If someone may be seriously ill, contact a qualified clinician or local emergency services.
